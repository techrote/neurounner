# VOID original DEVELOPMENT reference-byte budget v1

This *source-only research measurement*, not a model-quality result, checks
whether the **six original, positively native-admitted DEVELOPMENT teacher
programs** can be fully represented within VOID's actual byte-model context and
candidate completion ceilings. The two original host seeds for each design
are verified, not counted as twelve independent designs.

The script hashes the entire compressed ZIP as an opaque stream. It selectively
decompresses only manifest, DEVELOPMENT rows, and their visible source-bound
native receipts/readbacks/PNGs, checking positive admission and hashes. It
**never opens, decompresses, CRC-checks or evaluates sealed FINAL members**.
Only split metadata establishes non-overlap with FINAL. Source-qualified
VOID adapter/profile Git blob hashes are verified before import, preserving
strict UTF-8, native Qwen3 byte IDs, cybersand-void-task-v1 framing and a real
terminal EOS258. It does not download or instantiate the model or optimizer.

Output reports authentic full teacher completion lengths including EOS258,
prefix lengths, 2048-token headroom, and whether each original program fits
provisional 512 and previously used 768 completion tokens. This establishes
**reference representability only**; it cannot demonstrate that a model learns
when to terminate, outputs raw valid JSON, compiles, draws requested topology
or paints useful art. It also does not qualify the 60-request/five-formulation
benchmark: no new benchmark is frozen, no new TRAIN structures admitted.

The original 120-step VOID model remains at 6/6 EOS, 4/6 strict JSON,
1/6 compiler-accepted, 0/6 request-conforming DEVELOPMENT outputs.
Do not promote this source-only measurement into painter-quality evidence.
The GitHub-hosted result and its original uploaded report require actual
completion and independent inspection before claiming numerical outcomes.
