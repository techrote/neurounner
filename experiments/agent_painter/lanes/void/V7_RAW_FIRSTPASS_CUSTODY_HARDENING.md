# VOID raw-first-pass evidence verifier v2 — 14 November 2026

**Disposition:** lane-owned model-free custody hardening, not a new DEVELOPMENT evaluation, model generation, optimizer update, new TRAIN admission, native Art run or useful-vN freeze. The frozen original archives, the V6 historical audit and the shared foundation remain unchanged. PR #574 stays Draft/HOLD.

The V6 original-first-pass audit faithfully compared the original byte token IDs, UTF-8, EOS258, original receipts and original ZIP hashes, but its classification still *trusted* original `json_valid` booleans. This is a defensive verifier weakness: a future self-consistent altered receipt could claim malformed JSON is valid, or vice versa. Similarly, it had not independently tied accepted compiled operations and their SHA-256 to the original per-case receipt.

The v2 verifier now independently parses original completion text with the shared strict duplicate-key and nonfinite-constant semantics, demands exact equality with recorded JSON validity, authentic terminal EOS for any claimed first-pass acceptance, exact original completion SHA-256 and compiler-acceptance flag, and checks that accepted operation JSON matches `compiled.json` and receipt SHA-256. Rejected outputs must have empty operation arrays, no compiled record and no claimed operations digest. These checks are **custody and consistency only**, not independent compiler geometry, execution, recognition or artistic quality.

New adversarial tests cover forged true/false JSON flags, duplicate keys, NaN/Infinity, forged compiler acceptance, completion hash substitution, false acceptance without EOS, and a positive accepted compiled-operation example with negative digest substitution.
