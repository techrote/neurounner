# Conversation and orchestration topology notebook

This is a live design notebook for neurounner. The objective is not ordinary conversational quality; it is to discover model orders that produce, preserve, challenge, repair and select interesting behaviour mechanisms.

## Working roles

| Role | Current candidates | Purpose |
|---|---|---|
| chaos / mutation | Sprocket x3 | cheap divergent perturbation |
| cheap formatter/filter | LFM2.5-VL-450M text backbone | reject malformed/repetitive material cheaply |
| routine compiler | LFM2.5-1.2B-Instruct | turn fragments into bounded structured kernels |
| medium critic | Qwen3.5-2B, SmolLM3-3B, Ministral-3-3B | independent critique and constraint checking |
| slow incubator | Qwen3.5-4B, Phi-4-mini, Gemma-3-4B, Qwen3-4B | spend long runner time exploring/refining a population |
| deep periodic reviewer | LFM2.5-8B-A1B | occasional population-level reasoning and tie-breaking |

These roles are provisional. A model may prove more useful in a different slot after controlled comparison.

## Three-mutator funnel

~~~text
Sprocket A --\
Sprocket B ----> deterministic field validation -> LFM1.2 compiler -> candidate
Sprocket C --/
~~~

Foundry v1 showed that free-prose Sprocket output is too contaminated by meta-language. The next version should constrain each Sprocket to a tiny mutation record with fields such as trigger_delta, state_delta, action_delta and failure_guess.

Candidate identity and lineage must be assigned by the orchestrator, never generated by a model.

## Sprocket sandwich

~~~text
3x Sprocket mutation
      |
LFM1.2 compile/repair
      |
3-4B model deepen/challenge
      |
LFM1.2 compress back to KernelSpec
      |
deterministic validation
~~~

This topology places the slow model only where richer thought can add value. The final LFM pass removes accumulated prose and returns the result to a compact canonical representation.

Variants worth comparing include Qwen3.5-4B, Phi-4-mini, Gemma 3 4B, Ministral 3 3B and SmolLM3 in reasoning mode.

## Independent panel, not serial contamination

~~~text
                   -> Qwen3.5-4B --\
same candidate set -> Phi-4-mini ----> deterministic score merge / adjudicator
                   -> Gemma 3 4B ---/
                   -> Ministral 3 ---/
~~~

Each model receives the exact same immutable candidate set. Models cannot see one another's answers until the merge stage. This is useful for measuring genuine model-family disagreement instead of conversational anchoring.

Interesting signals include unanimous rejection, unanimous survival, one-model-only enthusiasm, disagreement about failure modes, disagreement about novelty, and different repaired kernels derived from the same parent. Disagreement can trigger an LFM8B review rather than being averaged away.

## Adversarial two-model workshop

~~~text
A: propose mechanism
B: find physical/semantic failure
A: repair without adding complexity
B: attempt counterexample
A: final compact kernel
validator
~~~

Good candidate pairings should be cross-family rather than two variants of the same model. Initial comparisons:

- Qwen3.5-4B vs Phi-4-mini
- Qwen3.5-4B vs Gemma 3 4B
- Ministral 3 3B vs SmolLM3 3B
- Qwen3-4B vs Qwen3.5-4B as a same-family control

The critic should receive explicit authority to kill a concept, not merely improve it.

## Alternating novelty / constraint loop

Odd turns are rewarded for making a real conceptual change. Even turns are forbidden from adding mechanisms and may only repair or simplify. This should reduce the common failure where every critic adds another layer until the kernel becomes an architecture diagram.

One candidate order:

~~~text
Sprocket or SmolLM3
        | novelty
LFM1.2
        | normalize
Qwen3.5-4B
        | deepen
LFM1.2
        | simplify
~~~

## Tournament bracket

Generate a population, then compare pairs rather than asking one model to rank a large list.

~~~text
A --\
     > winner 1 --\
B --/             \
                   > champion
C --\             /
     > winner 2 --/
D --/
~~~

This keeps contexts short, makes pairwise reasons explicit, permits judge-consistency measurements, and allows different model families to run the same bracket independently. Losers should remain archived because some may be novel but poorly expressed.

## Slow incubator / four-hour worker

A 3-4B model should not spend a four-hour job answering disconnected prompts. Give it persistent local research state such as population.json, notebook.md, rejected.jsonl, interesting_failures.jsonl and frontier.json.

A useful loop is: choose one frontier item or interesting failure; propose a bounded modification; self-critique against KernelSpec; compare with parent; retain both, one, or neither; periodically summarize what appears to have been learned about the design space; continue until the time/token budget is reached.

Every state transition is written by the orchestrator. The model proposes content, but cannot silently rewrite lineage or scores.

At four generated tokens per second for four hours, the raw ceiling is 57,600 completion tokens. A slow model is therefore worthwhile if it produces a better survivor rate per 10k tokens than faster alternatives.

## Archipelago

Maintain independent populations with different model ecologies:

- island A: Sprocket-heavy
- island B: Qwen-heavy
- island C: Gemma/Phi
- island D: Ministral/SmolLM
- island E: LFM-only control

Every N epochs, migrate one survivor and one interesting failure between islands. This tests whether a mechanism discovered under one model family can survive reinterpretation by another.

## Cheap gate before expensive thought

A possible order is:

~~~text
raw mutation
  -> schema check
  -> repetition/similarity check
  -> LFM-VL-450M cheap semantic gate
  -> LFM1.2 normalization
  -> 3-4B review only for survivors
  -> LFM8B only for disagreement / elite review
~~~

The 450M gate should be tested for false negatives before it gets authority to discard unique mutations.

## Conversation-memory variants

Do not assume more context is better. Test stateless handoff, parent-aware handoff, compact lineage-aware handoff, full transcript, and external curated notebook as separate conditions.

The working hypothesis is that full transcripts will create anchoring and stylistic contamination, while compact external state will preserve more mechanism diversity.

## Measurements that matter

Primary metrics should move away from raw tokens per second:

- valid KernelSpecs per runner-hour
- novel surviving mechanisms per runner-hour
- novel survivors per 10k generated tokens
- fraction of generated tokens that survive into final kernels
- schema and constraint failure rate
- duplicate rate
- lineage accuracy
- parent-mechanism retention after repair
- diversity between independent model families
- judge consistency on repeated blinded comparisons
- interesting-failure yield
- time to first genuinely useful survivor
- frontier improvement over a fixed four-hour budget

Raw generation throughput remains useful for capacity planning, but it should not determine model value by itself.
