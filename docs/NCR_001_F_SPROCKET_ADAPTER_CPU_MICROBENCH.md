# NCR-001F — measured, model-free Sprocket adapter CPU microbenchmark

**Issue:** #73. **Stack:** open draft PR #98. **Authority:** original four-lane protocol/source pins, original NCA implementation #69 and parameter-matched gated-MLP module. This is a narrow forward-only synthetic adapter kernel measurement, not a model-host comparison or training qualification.

## Scientific question and deliberately limited answer

The preregistered three-step, three-tap NCA and ordinary feature-gated MLP are close in trainable parameter count but have different work. Source arithmetic (not measured FLOPs) gives NCA **658,904** versus MLP **658,432** parameters, and NCA/MLP dense+convolution MAC proxy **1.20625x** (20.625% more counted operations for NCA). This proxy excludes nonlinearities, normalization, memory traffic, autograd and the frozen transformer.

The bounded CPU prepass runs the **actual PyTorch adapter classes** PersistentDepthNCA and GatedMLPControl with original 8x8x4 field, hidden size 1280, three taps and three NCA steps/tap. They receive identical deterministic synthetic [1,T,1280] hidden activations at each tap for **T=1,16,64**. State passes from tap to tap only in the NCA, never between requests. Neither model checkpoint, tokenizer nor held-out fixture is downloaded or executed; these are not frozen LM activations.

Both zero-readout modules must exactly return their respective input activations at all three taps before timing. Unregistered geometry, changed source Git blobs, altered training authorization, malformed lengths/budgets, changed module parameter counts and nonfinite NCA fields are fatal. The same CPU process alternates adapter timing order with two unmeasured warmup rounds and five recorded rounds per adapter/length, torch.inference_mode(), float32, four CPU threads and fixed seed 20261029. Raw milliseconds and medians are retained; no general speedup or efficiency claim follows from a single CPU-host sample.

The report preserves distinct pinned Chat chat/model.safetensors and root-Instruct model.safetensors identities, but **shared geometry is measured only once**. Timings are not checkpoint-specific and must never be transferred to either #72 frozen-model scientific lane. CPU, OS, Python/PyTorch package identity, exact branch/head/Actions run/attempt, source SHA-256s, source Git-blob checks, complete raw timing samples and peak process RSS are captured. Peak process RSS is not adapter incremental RSS.
